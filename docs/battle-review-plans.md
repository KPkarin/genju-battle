# AIの再評価基準・対戦記録の設計案（2026-11-23）

今回実装するのはUIのみ。ログ速度・AIの選択・技・特性・能力値・相性・記録収集は変更しない。

## AI再評価の方針（提案、未実装）

目的は勝率だけでなく「特性と技の意図が伝わる」「無意味な行動を繰り返さない」こと。相手の未確定入力、乱数の未来、非公開情報を参照しない。自分の編成、公開された状態、既知の相手の行動だけを使う。人間の選択確定後でも、その選択をAIの材料にしない。

### 共通の評価単位

行動の評価を、お互いの最大HPに対する割合と行動機会へ正規化する。基本案：

`Q = 期待与ダメージ率 + 有効回復率 + 将来の利益 − 予測被害率 − 気力の機会費用 − 失敗・固定のリスク`

これは未調整の設計式。係数を恣意的に決めて強弱判定を確定させない。まず各項を別々に記録し、公開情報から予測できる範囲を明示する。

- 期待与ダメージ：命中・相性・一致・天候・攻撃能力・特性・持ち物・連続技の各打撃を反映。乱数は平均0.925、急所は期待値で扱い、対戦用乱数を引かない。超脚力・音技・腕ピース・速度参照を実ダメージと同じ純粋計算の部品に揃える。
- 回復：最大値を超える分はゼロ。回復で下がる流血、攻撃を受ける前か後か、その後に耐えられるかを分ける。
- 行動阻害：発動確率だけでなく、免疫・既存状態・身代わり・先後・残り期間を反映。「成功しても止める行動がない」は低評価。
- 製氷：蓄積段階、凍結無効、既存凍結、再凍結、残り気力を評価。威力30だけで評価しない。
- けんけんま：3ターンを使う技として、準備中の生存・妨害・最後の2発・完走後の能力変化を別評価。威力160を即時攻撃と同列にしない。
- 守る：相手の既知の技・設置・天候・継続ダメージ・自然回復・連用コストを反映。相手の未確定技を透視しない。
- 強化・弱体化：対応する攻撃技があるか、上限か、相手の攻撃分類と継続見込みを見る。
- 交代：設置で落ちる危険、能力変化の喪失、再生・登場特性、相手が既に見せた技を考える。タイプだけで頻繁に往復しない。
- 気力：今回の実消費、次の連用加算、自然回復12、気力溜め時の被ダメ増加まで見る。単純な威力÷基本気力では決めない。

### 段階的な導入と検証

1. まず現AIの各候補について評価の内訳だけを開発用に出す。選択はまだ変えない。
2. 特性・持ち物補正と無効行動の除外を共通化する。
3. 2〜3行動先の軽い読みを追加。多数の未来乱数を消費する探索ではなく期待値を使う。
4. 旧AIと新AIを同じ対戦条件・先後入れ替えで比較。勝率、無効行動、過剰回復、同じ妨害の空打ち、交代往復、平均ターン数を測る。

難易度は数値の水増しや情報透視ではなく、探索深度・既知情報の使い方・選択のばらつきで分ける。

## 対戦記録の方針（提案のみ、未実装）

### まず端末内の記録から

初期は任意のON/OFF付きで、自分の端末に保存する。外部へ自動送信しない。名前、合言葉、接続ID、IPアドレスを記録しない。対人戦の相手の未公開情報は保存・表示しない。利用者が明示的に書き出したJSONだけを共有可能にする。

ルール版・AI版・画面版・記録形式版を分ける。数値調整前後の戦績は混ぜず、通常戦・ボス戦・対人戦・AI検証戦も別集計にする。UI更新だけではバランスの集計区分を分断しない。

### 保存する3層

1. **試合情報**：ランダムな記録ID、日付、モード、各バージョン、結果、ターン数、終了理由（勝敗・切断・離脱）。自分側の編成と技・持ち物・特性。相手側は公開済みの情報のみ。
2. **出来事**：試合ID・ターン・処理順・行動者・対象・原因ID・実際の結果。選択時のスナップショットと、解決後の結果を区別。UIの描画やログ再表示では記録しない。
3. **集計**：幻獣別・構成別・技別の出場回数と試合数、勝敗、与被ダメージ、有効回復、気力、行動機会、状態異常による停止など。

具体的な出来事：

- 技：選択／強制／実行を区別。命中・外れ・無効・守る・身代わり・対象不在・行動不能・気力不足を別の結果コードにする。
- ダメージ：直接攻撃、身代わり、天候、やけど、流血、反動、やけくそ、設置、その他を原因別にする。複数回攻撃は技1回＋打撃ごとの子イベント。過剰ダメージと実HP損失を区別する。
- 回復：要求量と実回復量を別保存。吸収、道具、特性、技、天候を分ける。HPが上がらなかった回復を有効回復や流血軽減に数えない。
- 状態：付与の試行と成立、免疫、防御、やせ我慢による予約、発症、解除、再付与を別保存する。
- 行動機会：行動不能の表示回数ではなく、予定されていた行動が実際に失われた回数を数える。凍結・眠り・麻痺と、自分が選んだ反動・継続準備を分ける。
- 交代：手動／翻し／瀕死補充を区別し、設置被害と登場効果を紐付ける。
- 気力：基本消費、連用、道具・特性などの加算、実消費、自然回復、気力溜めを分ける。

二重記録防止には `試合ID / ターン / 行動番号 / 打撃番号 / イベント番号` を使う。ネット対戦は各端末で観測した自分の試合を記録し、共有ファイルを取り込む場合だけ同一試合の照合・重複排除を行う。切断や未完了試合は勝率の分母へ勝手に加えない。

### 保存容量と耐障害性

イベント列はIndexedDB、設定だけをlocalStorageへ分離し、既存の編成保存キーを維持する。初期案は直近100試合または20MBまでのいずれか早い方。古い詳細を削除する前に集計だけ残すかを選べるようにする。容量不足や保存不可でも対戦を止めない。終了確定前の試合には未完了フラグを付ける。全削除・書き出し・取り込みと形式版チェックを提供する。

対人戦では裏に残った未公開の技・持ち物などを、終了後だからといって勝手に公開しない。完全な再現用seed・入力列は公開情報だけの戦績と分離し、初期の記録機能には含めない。

### 最初の集計画面

「戦績」から、期間・ルール版・モードで絞り込む。上段は試合数・勝敗・平均ターン数。次に幻獣別の採用／選出／出場、技の実行／命中／失敗理由、有効回復、行動停止を表示。少数試合は試合数を併記し、ランキングで強弱を断定しない。対人とAI相手、同じ編成での連戦は分けて見られるようにする。

例：製氷は「使用率」だけでなく、命中何回目で初凍結したか、同じ相手を再凍結したか、凍結によって何回の行動が失われたかを見る。けんけんまは開始数・完走率・中断理由・準備中の被害・完走後の利益を追う。

### 記録が揃ってから判断する保留事項

- **4：製氷**：雪かきとの組合せ、初凍結／再凍結、気力制限と行動停止回数を確認する。
- **5：けんけんま**：拘束との組合せ、回避の影響、完走率と対抗策を確認する。
- **6：能力合計と配分**：550の合計だけで揃えず、役割・耐性・回復・実効火力・速度帯別に比較する。
- **7：野生属性**：採用率・対面・一致野生技の選択、他属性から借りる場合との差を確認する。

個人の数試合だけで数値調整を確定しない。まず疑わしい構成を抽出し、同じ編成条件・先後入れ替え・複数seedの検証戦で再現性を確かめる。必要試合数は効果の大きさと不確実性に応じて決め、勝率には試合数と信頼区間を併記する。記録機能を導入するまで、上の4項目の数値は保留。
